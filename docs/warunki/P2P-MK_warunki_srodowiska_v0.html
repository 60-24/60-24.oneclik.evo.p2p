P2P-MK v0: warunki środowiska i urządzeń

Status: propozycja AI-D z delegacji Architekta, 2026-11-08. Wersja zasad: v0.

Zasada nadrzędna

Brak progu wiekowego. Urządzenie jest dopuszczone, jeśli spełnia minimum techniczne. Pozostałe warunki tylko informują i nie blokują.

Poziomy wyniku preflight

BŁĄD blokuje start węzła. Tylko dla warunków bez obejścia.

OSTRZEŻENIE węzeł startuje w trybie ograniczonym, z opisem skutku.

OK warunek spełniony.

Co nie jest warunkiem

  • Wiek urządzenia i rok wydania (nie ma progu lat).
  • Konkretny model lub producent.
  • Szyfrowanie: w v0 nieobowiązkowe, od v0.2 wymagane.

Test referencyjny (pomiar, nie bramka)

Zapis czasu utrzymania połączenia, przyczyny zerwania i stanu z preflight. Wynik to dane do decyzji, nie warunek dopuszczenia.

Otwarte

  • Minimum API zostaje 23 (bez zmiany w APK v0.1.0). Do rewizji po teście.
  • Preflight jako osobny moduł L3 lub część kernela: do decyzji Architekta.
