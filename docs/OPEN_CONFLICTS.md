# P2P 60-24 — Open Conflicts Register

**Phase:** 3
**Status:** OPEN / CONTROLLED

This register prevents silent resolution of contradictions found during reconstruction.

## C-001 — Project architecture vocabulary

**Conflict:** Historical documents use several overlapping architectural vocabularies: OmniKernel / Kernel, SEE / Structural Evolution Engine, SFO, TAL, KERNEL-DNA, Cognitive Fabric, AIRN and related layers.

**Current treatment:** Do not delete or merge concepts yet.

**Required resolution:** establish canonical entity names, hierarchy and version provenance in the ontology audit.

## C-002 — Trust / Reputation terminology

**Conflict:** Older material uses Reputation, Reputation Manager, Reputation Ledger and TrustGraph/Trust Infrastructure with partially overlapping meanings.

**Current treatment:** Trust Infrastructure is the current protected boundary; identity ≠ trust ≠ reputation.

**Required resolution:** define exact ontology and permitted relations.

## C-003 — Economic / Happycoin concepts

**Conflict:** Earlier material contains economic and token-like concepts, while current project boundaries explicitly exclude financial token/wallet/payment architecture.

**Current treatment:** historical only unless a future constitutional decision explicitly changes the boundary.

## C-004 — Impact framework

**Conflict:** Earlier documents propose multi-dimensional impact indices and a broad mission around measurable positive impact. Their status relative to the current Project Constitution is not yet formally approved.

**Current treatment:** historical/unverified proposal; preserve for review, do not encode as a frozen system requirement.

## C-005 — Technology choices

**Conflict:** Historical proposals mention combinations such as libp2p, WebRTC, Yjs, CRDT variants, MCP services and multiple language/runtime choices.

**Current treatment:** technology choices remain implementation candidates, not constitutional facts.

## Resolution rule

No conflict is resolved merely by deleting one document. Resolution requires provenance, comparison, explicit decision and—when constitutional or architectural—appropriate human review.
