# SES-003 — DEC-001: System Builder Definition

**Status:** APPROVED
**Session:** SES-003
**Step:** 1 — Definition of System Builder
**Date:** 2026-09-04

## Decision

The project adopts the following working definition of **System Builder**:

> **System Builder is a human-sovereign, graph-first metasystem that transforms human-defined intent into a model, architecture, contracts, implementation and a verified operating target system, while preserving traceability of meaning, decisions, evidence and changes throughout the system lifecycle.**

## Fundamental Relationship

```text
SYSTEM BUILDER
      |
      +--> understands intent
      +--> models meaning
      +--> designs system
      +--> builds system
      +--> verifies system
      +--> observes system
      +--> supports controlled evolution
      |
      +--> TARGET SYSTEM
             |
             +--> P2P 60-24 OneClick Evo Positiv (first target)
```

P2P 60-24 is therefore a **target system**, not the definition of System Builder itself.

## Core Lifecycle

```text
UNDERSTAND -> MODEL -> DESIGN -> BUILD -> VERIFY -> OBSERVE -> EVOLVE
```

## Human Sovereignty

Human defines intent and approves constitutional and fundamental architectural decisions. AI may analyse, propose, implement and verify within defined autonomy boundaries.

## Source of Truth

The repository remains the authoritative project source of truth. Conversation history is not authoritative when it conflicts with repository artefacts.

## Evidence Principle

A generated artefact or claim is not equivalent to proof of correctness. Significant claims require appropriate tests, observations, evidence and validation.

## Explicit Non-Goals

System Builder is not:

- merely an AI code generator;
- the owner of project intent;
- a replacement for human constitutional authority;
- a substitute for the target system itself;
- permission for AI to silently change constitutional or ontological assumptions.

## Consequence

Before designing or implementing System Builder technology, the project must define its boundaries, responsibilities, authority and interfaces with the target system.
